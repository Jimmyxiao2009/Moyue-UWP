# 墨阅 · Windows 10 Mobile 漫画阅读器功能规划

状态：此文保留原功能与交互规划。后端及 UWP 开发壳已经实现，前端由用户另行安排；实现范围见 [后端交接](BACKEND-HANDOFF.md)，实际验证范围见 [验证记录](BACKEND-VALIDATION.md)。尚未完成 10586 真机验收。
名称“墨阅”为暂定。目标设备：Lumia 930，Windows 10 Mobile 10586。

## 产品目标

接入 JM、香香腐宅、漫蛙，统一搜索、收藏、阅读、下载及历史。优先保证长章节阅读稳定、阅读进度可靠保存、已下载章节完整离线可读。

采用 C#、UWP XAML、MVVM；最低系统版本 10.0.10586.0，手机 ARM 32 位包。控件、NuGet 依赖及图片解码能力均须按这一基线验证。设计使用经典 Windows Phone 的深色、大标题、Pivot 与底部 CommandBar，可在旧系统上实现。

## 页面与导航

主导航：书架、发现、搜索、下载。底部命令栏的更多菜单提供历史及设置。详情、阅读器和高级搜索为独立页面，系统返回键返回上一层。

| 页面 | 首版功能 | 主要交互 |
| --- | --- | --- |
| 书架 | 收藏、来源筛选、最近阅读排序、继续阅读、批量移除收藏 | 封面进入详情，继续阅读进入上次章节 |
| 发现 | 来源切换，各源支持的推荐、分类、最新列表 | 选择来源后浏览；不支持的栏目不虚构 |
| 搜索 | 三源联合搜索、单源搜索、搜索历史、本地资料搜索、漫画 ID 直达 | 结果分来源标记，进入详情，进入高级搜索 |
| 高级搜索 | 来源多选、关键词匹配、排除词、作者、标签、可用状态筛选、排序 | 应用后进入结果页并显示生效条件；重置不清除搜索历史 |
| 漫画详情 | 封面、简介、作者与标签、来源、章节、收藏、续读、章节下载 | 已读和已下载状态区分；弹出章节多选下载面板 |
| 阅读器 | 纵向滚动、横向翻页、缩放、页码、章切换、阅读进度恢复 | 点中央显隐工具栏；目录、模式和亮度入口放在工具栏 |
| 下载 | 进行中／已完成、按漫画与章节组织、暂停、继续、取消、重试、删除 | 展示已完成页数、总页数及失败原因；完成后可离线阅读 |
| 历史 | 时间分组、来源标记、章节和页内进度、续读、删除和清空 | 点击续读；清空历史需明确确认 |
| 设置 | 深浅主题、阅读方向、预加载、仅 Wi-Fi 下载、缓存容量、缓存清理 | 缓存与主动下载分别管理；恢复默认不删除用户数据 |
| 来源与线路 | 三源发布入口、自动同步、自动换线、当前线路、手动选线和检查连接 | 按来源独立管理，同平台换线保留漫画身份和进度 |

## 三源高级搜索（首版核心）

### 搜索范围

- 默认选择三家，可独立勾选 JM、香香腐宅、漫蛙，至少选择一家。
- 在线搜索与本地资料搜索分开显示。本地资料索引来自收藏、历史及已保存详情，并不是全站数据库。
- 漫画 ID 直达要求先选择一个来源；不能把同一个 ID 当作三个源里的同一本漫画。
- 每个源独立请求、分页、超时和重试。结果可以逐源到达，一个源失败不会遮住其他结果。

### 条件与能力边界

| 条件 | 统一体验 | 实现约束 |
| --- | --- | --- |
| 标题／关键词 | 多关键词，匹配全部／任一，保留原输入 | 各源尽量映射到原生搜索；额外匹配规则需要对返回数据再核验 |
| 排除词 | 支持多个排除词，明确作用于标题或标签 | 仅能过滤已获得的数据；不等于各源服务器支持排除语法 |
| 作者、标签 | 独立输入及可移除条件标签 | 有原生能力时下推；否则仅在已加载且字段完整的结果中筛选 |
| 连载／完结 | 按可获得状态筛选 | 状态未知不伪装成连载或完结；无法筛选时显示不可用原因 |
| 排序 | 相关度、标题、最近更新（可用时） | 跨源相关度只作应用侧排序，不虚构统一热度或更新时间 |

结果页显示来源、每源状态、生效条件和“筛选已加载结果”等必要提示。分页继续加载后重新应用条件，不能把“当前未匹配”误报为“全站没有”。部分来源不支持的条件需在高级搜索页和结果页明确表达，不能静默忽略。

### 改善 JM 搜索体验

保存常用查询与搜索历史；支持 ID 直达；统一标题空白等轻量匹配处理；本地资料索引允许离线找回已接触的漫画。真实线上搜索质量取决于 JM 当前接口，接口尚未验证，不承诺全站索引、未验证 API 或绕过访问控制。

## 数据与下载规则

- 漫画主键为来源 + 来源漫画 ID，章节亦绑定来源；不同来源同名漫画不自动合并。
- 收藏、历史、阅读进度、下载队列和元数据使用本地持久化。首版不要求 App 账号，不承诺云同步。
- 阅读进度包含章节 ID、页号、滚动相对位置，在翻页、切章和挂起时保存。
- 图片缓存和主动下载分别管理；清理缓存不删除已下载章节，删除下载不删除收藏和历史。
- 下载保存章节顺序与清单，只有所有必要图片写入并通过基本检查后才标为完成。中断后恢复并补齐缺页。
- 图片 URL 可能过期，下载持久化章节身份而不只保存 URL；必要时重新解析。
- 预加载起步为后两页，下载并发起步为两张，按真机性能调整。长条图需要验证低内存下的缩放／解码策略。
- 后台传输、图片后处理和队列调度分开验证，不承诺 App 终止后所有章节可无限继续解析处理。

## 设计需覆盖的状态

书架空状态；搜索前／搜索中／部分来源失败／无匹配／本地结果；高级条件不可用；详情加载失败；章节未缓存断网；阅读图片失败重试；下载等待／进行／暂停／失败／完成；缓存清理和删除下载的区别。

原型使用虚构漫画资料和中性封面示意，不代表三家的真实结果。原型中的进度及联网状态均为交互演示，不能当作已实现功能。

## 实现顺序与验收

1. 验证编译环境、10586 ARM 真机安装，检查三源的搜索、详情、章节、图片与格式兼容性。
2. 先打通一个源的搜索 → 详情 → 阅读，建立统一适配器和搜索能力描述。
3. 完成三源联合与高级搜索；验证部分失败、分页以及本地筛选边界。
4. 完成收藏、历史、续读、下载恢复、离线阅读和设置。
5. 真机检验长章节、快速翻页、锁屏恢复、断网、存储不足及长时间内存占用。

验收要求：三源能搜索并阅读；筛选的实际作用范围清楚；重启保留收藏和进度；下载完成后飞行模式仍能打开完整章节；单源失败不拖垮全局；长阅读不出现持续增长的图片内存。

## Lumia 930 / 10586 专项性能方案

- 老设备优化默认开启。封面列表使用虚拟化和回收容器，分页加载，封面按显示尺寸解码；避免一次性创建完整书架或全部章节图片。
- 阅读图片采用有容量上限的缓存，按当前页面和前后窗口保留，快速跳转取消过期任务；内存压力升高时释放远端图片、减少预加载和解码并发。
- 网络 I/O 使用异步并发；WebP 解码、必要的图片还原和压缩单独限流，初始仅一个重处理任务。下载并发不能等同于同时全尺寸解码的数量。
- 根据图片尺寸估算 BGRA 峰值（宽 × 高 × 4），检查长度和溢出，超长图片先验证分块／缩放解码能力。不能先完整解码再缩小而声称已降低峰值。
- `BitmapImage.DecodePixelWidth` 等可按显示需求限制解码尺寸；参考 [UWP BitmapImage 文档](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.media.imaging.bitmapimage)。可用的 `MemoryManager` 事件和内存限额应按 10586 验证，不能直接套用后续版本生命周期 API。
- 尽量使用原生 WinRT 解码器或验证后的 ARM32 组件，减少 BGRA 数组及 WinRT Buffer 往返复制；离开页面及时释放流和图像引用。
- 下载与阅读共用去重和请求调度，当前阅读优先，数据库及磁盘写入批量化；挂起前保存队列，恢复时重新附加系统传输与检查本地清单。
- 性能验收使用 Release ARM 真机：冷启动、长章节、快速跳页、同时下载、锁屏恢复、失败重试。记录耗时、峰值内存、长期内存趋势及有效下载速度，指标在实测后确定，不能预先承诺固定帧率或速度。

## 多线程下载与可靠性

产品称为“并发下载”；实现为有界异步 worker，默认两张，可设 1／2／3／4／6。阅读优先与低内存降速默认开启，实际有效并发可能低于设定上限。图片解码独立串行／有限并行，避免每个网络 worker 同时解码长图。

提供全部暂停／继续、取消、调整队列、仅重试失败页、重启续传、仅 Wi-Fi；逐页记录等待／获取／处理／验证／完成／失败。UI 展示成功页数和失败页数，不以已尝试次数充当完成进度。

临时文件通过验证后原子提交；断点 HTTP Range 仅在服务器支持且资源身份未改变时使用，否则重新下载单页。重试有次数限制、退避和取消，不无穷刷失败地址。空间不足先停止启动新页，保留已经完成的页。

旧项目 `H:\项目\UWP\jmuwp` 只作为只读参考：
- `app/Jm.Uwp/WebpDecode.cs` 和 `libs/ARM/Universal.WebP.dll`、`.winmd` 已存在。README 描述在 15254 上验证，尚不能证明 10586 兼容；检查组件依赖和 Release ARM 真机后决定复用。
- `JmDownloader.cs` 使用 `SemaphoreSlim` 控制并发，但 `finally` 中无条件增加 done，且 `SaveOneAsync` 失败返回 null 后仍能登记整章；新实现须修复成功计数及整章完成判定。
- 首个成功域名被固定后，单页失败没有重新尝试其他域名；新方案允许回退且保持请求级地址快照，避免多任务修改候选表的竞态。

## 从发布页同步地址并自动换线

- “换线”指同一来源内切换备用网址／API 地址／图片 CDN，三者分开维护；不自动把 JM 的漫画换成另一个来源的同名漫画。
- 同步触发：用户手动、进入在线功能时缓存过期（初始 24 小时）、当前地址失败且已有候选不可用。启动先展示本地资料，同步不阻塞书架；无网络或飞行模式不反复探测。
- 发布页和数据端点可能格式不同，每个源使用明确解析规则。仅提取其发布的阅读／API 地址，不执行任意远端脚本，不把广告、下载 APK 或统计链接当漫画服务。
- 新候选通过来源特征及服务能力检查后才启用；API／图片／网页健康分别判定。缓存最近可用列表及发布时间／同步时间，空列表、失败响应或结构变化不覆盖有效旧配置。
- 失败时对少量备用节点做有界检查，记录超时和冷却期，避免每一张图片都同步一次发布页。全局断网不引发无意义轮换；登录失效提示重新登录，而不无限换网址。
- 地址变化不改变来源 ID、漫画 ID 和下载清单；恢复当前章节时重新解析必要链接。域名切换只携带该源必要凭据，不把会话凭据泛化发送给任意新主机。
- 界面提供自动同步／自动换线开关、发布入口、最后成功时间、当前与候选线路、手动选线、检查连接、同步失败原因及缓存回退提示。
- 自动换网址只能在存在可访问的备用线路时恢复连接，不能保证全部被封时仍然可达。此时保留离线阅读入口，并允许编辑发布页配置。

发布入口调查及可信度记录见 [SOURCE-RESEARCH.md](SOURCE-RESEARCH.md)。当前阶段是设计和资料调查；原型只演示状态变化，没有真实执行联网同步、多线程下载或图片解码。
